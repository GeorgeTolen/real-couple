# PROMPT: презентация v2 «Живой журнал» (анимация, типографика, компоненты)

Ты Claude Code (Opus 5.5) в репозитории `real-couple`. Задача: переделать готовую презентацию `pitch/slides/`, чтобы она стала динамичнее, а шрифты и компоненты интереснее. Это **доработка поверх текущей сборки**. Сохраняем структуру, данные, клавиши и экспорт. Работаем аккуратно: до 12:00 идёт сдача, бюджета на эксперименты почти нет.

Используй скиллы `frontend-design` и `vizavi-motion`, если они есть. Сначала прочитай:
- `pitch/slides/src/{slides.ts, style.css, main.ts, data.ts, coins.ts}`, `pitch/slides/README.md`, `pitch/slides/numbers-check.md`
- `docs/pitch/PROMPT_slides.md` (исходное ТЗ) и `docs/pitch/data/*.json` (единственный источник цифр)
- `frontend/src/app.css` (токены продукта)

## 0. Что нельзя ломать

1. **Цифры.** Не трогай значения, бери их только из `docs/pitch/data/*.json`. После правок `npm run check` и `numbers-check.md` должны проходить без изменений.
2. **Шаги.** Механика `data-s` и `steps` остаётся. Каждое новое движение привязывай к шагу: ведущий жмёт пробел, и что-то происходит.
3. **Экспорт.** `scripts/export.mjs` вызывает `deck.goto(i, 'last')` и делает скриншот. Последний шаг каждого слайда в PNG и PDF должен выглядеть законченно: никаких полупрозрачных кадров, счётчиков на середине, пустых путей. Добавь в `deck` флаг `settle()` или ожидание `document.getAnimations()`, чтобы экспорт снимал кадр после всех анимаций.
4. **Клавиши** N, G, F, P, стрелки, Home и End работают как раньше. Режим ведущего тоже.
5. **Тон.** Корпоративный финтех, светлый фон `#f6f5f1`, зелёный `#138a4e`, хром `#0e3b27`. Без неона, свечения, градиентов «как у ИИ», эмодзи и мультяшности. Без длинных тире в тексте.
6. **Одна HTML.** Сборка остаётся single-file через `vite-plugin-singlefile`. Новые зависимости только если они маленькие. Лучше обойтись CSS, Web Animations API и SVG. GSAP и Framer не подключаем.
7. **Без мерцания.** `prefers-reduced-motion` и `body.instant` выключают всё движение. Остаются только смены прозрачности по 120 мс.

## 1. Типографика: три голоса и одна «звезда»

Шрифты уже лежат в `@fontsource-variable/*`. Если `node_modules` нет, выполни `npm ci` в `pitch/slides`.

| Роль | Шрифт | Как используем |
|---|---|---|
| Дисплей | **Unbounded** (вариативный, 200 до 900) | Заголовки и герой-числа. Вес анимируется: заголовок въезжает тонким (wght 250) и «наливается» до 700 за 700 мс. Межбуквенный −0.02em, кегль 88 до 128 px |
| Акцент-эксперимент | **Geologica** | Проверь в `node_modules/@fontsource-variable/geologica/files`, есть ли файл `*-full-normal.woff2` с осями `CRSV`, `SHRP`, `slnt`. Если есть, это наш «живой» шрифт для одного слова в заголовке и подписей шагов: слово ловит фокус через `slnt 0 → -8` и `SHRP 0 → 100`. Если файла нет, бери wght и `font-style: oblique` |
| Текст | **Onest** | Абзацы и подписи, 24 до 32 px, вес 400 и 500. Не анимируется, это опора для глаза |
| Данные | **JetBrains Mono** | Все числа, коды критериев (`c1…c8`), id диалогов, `$0.021`. Всегда `font-variant-numeric: tabular-nums slashed-zero`, чтобы счётчики не «прыгали» по ширине |
| Цитаты | **Source Serif 4 Italic** | Только карточки цитат из исследования. Подключи cyrillic-файл: сейчас подключён только latin, и русский текст падает в запасной шрифт. Проверь глазами |

Правила:
- Крупное число всегда крупнее заголовка. Герой-цифра 200 до 280 px, Unbounded 800, рядом подпись Onest 24 px цветом `--text-2`.
- На слайде не больше двух начертаний дисплея.
- Акцентное слово заголовка выделяем цветом `--accent` и тонкой линией под ним, которая прорисовывается слева направо (`scaleX 0 → 1`, origin left, 500 мс, задержка 250 мс). Не жирностью и не плашкой.
- Не больше 7 слов в заголовке и 12 слов в подписи. Всё остальное превращаем в графику.

## 2. Язык движения (токены)

Добавь в `:root`:

```css
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);      /* въезд, основное */
--ease-io: cubic-bezier(0.65, 0, 0.35, 1);      /* перестройки, морфы */
--ease-snap: cubic-bezier(0.3, 1.3, 0.5, 1);    /* только мелкие отметки: галочки, точки. Перелёт не больше 4% */
--t-1: 180ms; --t-2: 420ms; --t-3: 720ms; --t-4: 1100ms;
--stagger: 45ms;
```

Принципы:
- **Одно главное движение на шаг.** Остальное подыгрывает с задержкой и меньшей амплитудой.
- Анимируем только `transform`, `opacity`, `clip-path`, `stroke-dashoffset` и `font-variation-settings`. Не анимируем ширину, высоту и top/left, кроме уже существующих мест.
- Въезд снизу на 24 px плюс маска (`clip-path: inset(0 0 100% 0) → inset(0)`), а не просто fade.
- Выход быстрее входа: 60% длительности, вверх на 12 px.
- Зацикленное движение разрешено только фоновое и тихое (пакеты по стрелкам архитектуры, монеты). Пауза, если вкладка скрыта.

Сделай маленькую библиотеку `src/motion.ts` (около 150 строк):
- `splitWords(el)` и `splitChars(el)`: оборачивает в `span` с `--i`, сохраняет пробелы и переносы, ставит `aria-label` на родителя.
- `reveal(el, {mode: 'mask'|'rise'|'weight', delay})` на Web Animations API.
- `countUp(el, to, {decimals, prefix, suffix, duration})`: одометр по разрядам (см. ниже). Округление ROUND_HALF_UP как в продукте.
- `drawPath(path, duration)`, `flip(container, mutate)` (First, Last, Invert, Play для перестановок).
- `settled(): Promise<void>` ждёт все `document.getAnimations()`. Его использует экспорт.

## 3. Переходы между слайдами

- **View Transitions API** (`document.startViewTransition`). Через `view-transition-name` проходят сквозные элементы: логотип, номер слайда, полоса прогресса, а также **герой-число**, если оно повторяется на соседнем слайде. Пример: 97.7% модели Sol из турнира морфится в карточку судьи B на архитектуре.
- Обычный переход: старый слайд уходит вверх на 16 px и тает (`--t-2`), новый собирается по шагу 1.
- **Переход к новой главе** (исследование → турнир → архитектура → результат → наше): шторка цвета `--chrome` проходит слева направо за 600 мс. На ней 400 мс видна надпись главы (Unbounded 300, 64 px, `--chrome-text`), например «02 Турнир моделей». Потом шторка уходит.
- Полоса прогресса внизу в 4 px, `--accent`, шириной равна доле пройденного. Деления по главам.
- Если View Transitions нет (Firefox) или включён reduced motion, остаётся обычный crossfade 200 мс.

## 4. Компоненты (переделай или добавь)

Порядок слайдов прежний: title, cover, research, tournament, architecture, difficulty, journey, demo, result, ours, next и бэкапы R1 до R4. Для каждого описан «герой-момент».

### 4.1 Одометр-счётчик (общий)
Каждый разряд это колонка цифр 0 до 9 в маске высотой одну строку. Колонка уезжает по Y до нужной цифры. Старшие разряды останавливаются раньше младших (задержка 40 мс на разряд справа налево), и число «встаёт на место». Точка и знак `$`, `%`, `/` статичны. Последний кадр: обычный текст для экспорта и копирования.

### 4.2 title
Тенге-монеты three.js остаются, добавь лёгкий параллакс: на каждом шаге камера сдвигается на 2 до 3 градуса. Заголовок `CQA` собирается по буквам с weight-sweep. Подзаголовок проявляется маской. На шаге 2 тонкая зелёная линия прорисовывается под названием команды.

### 4.3 cover (масштаб проблемы)
Сетка плиток «диалогов», 13, 46 и 82 подсвечены. Сделай волну: плитки заливаются по диагонали (`--i` по сумме строки и столбца), затем три выбранные слегка увеличиваются (scale 1.06) и получают галочку с `--ease-snap`. Число справа идёт одометром.

### 4.4 research (статьи → решения)
Колода карточек цитат. Карточки лежат стопкой с небольшим поворотом (±2°). На каждом шаге верхняя карточка «вытягивается» вправо на своё место в сетке 2×2 (FLIP). На обороте, в нижней части карточки, проявляется наше решение (`decision` из `QUOTES`). Цитата Source Serif Italic, источник чипом JetBrains Mono. Цитаты не длиннее 15 слов (уже так в `research.json`).

### 4.5 tournament (16 моделей)
Scatter «цена × точность»:
1. Шаг 1: оси прорисовываются, точки падают сверху на свои места с `stagger` по цене (от дешёвых к дорогим).
2. Шаг 2: фронт Парето рисуется линией `drawPath`, точки вне фронта гаснут до 35%.
3. Шаг 3: три выбранные модели поднимаются (`scale 1.4`), вокруг каждой один раз расходится кольцо. Подписи-теги выезжают от точки по короткой выноске. Их точность на подписи идёт одометром.
Наведение мышью (для живой демонстрации): точка тянется к курсору на 6 px («магнит»), во всплывашке модель, точность и цена.

### 4.6 architecture (конвейер)
Главный слайд для жюри.
- Узлы появляются по колонкам слева направо (`COLUMN_OF`), стрелки прорисовываются вслед.
- **Токен диалога**: маленькая плашка `ru-020` (JetBrains Mono, 16 px, белая на `--chrome`) едет по маршруту через `offset-path` с путём из `route()`. Возле судей A и B она **раздваивается**: две копии идут параллельно. На «check» они сходятся. Если по шагу есть спор, одна ветка краснеет и уходит в «arbiter». Потом токен приходит в «score», и там одометром выпадает `92.31`.
- Узлы ИИ (judgeA, judgeB, arbiter) при прохождении токена «вдыхают»: обводка 1.5 → 3 px и обратно, 300 мс. Без свечения.
- Подсветка шагов `HIGHLIGHT` сохраняется: остальное приглушается до 28%, как сейчас.

### 4.7 difficulty (сложность критериев)
Горизонтальные бары c1 до c8. Шаг 1: бары растут из нуля в порядке кодов. Шаг 2: **гонка-сортировка** через FLIP, бары переставляются по убыванию точности (c3 99.4 сверху, c7 71.2 снизу) за `--t-3` с `--ease-io`. Шаг 3: три самых трудных получают флажок и короткую причину (из данных, не выдумывать).

### 4.8 journey (как мы шли)
Горизонтальная лента-таймлайн с бегунком. Каждый шаг двигает бегунок к следующей вехе, линия прогресса заливается, веха раскрывает карточку. Где есть «до/после» (например, пилот 85 → калибровка), старое число зачёркивается линией и съезжает вниз, новое въезжает одометром. Время вех из `journey.json` моноширинным шрифтом.

### 4.9 demo
Скриншоты из `docs/screens/2x/` в рамке окна (радиус по правилу: внешний = внутренний + отступ). Переход между скриншотами: Ken Burns 3% плюс фокус-рамка, которая прорисовывается вокруг важного места (октагон, паспорт критерия, апелляция). Курсор-указатель (простая стрелка SVG) плавно доезжает до места клика. Никаких оранжевых рамок.

### 4.10 result (цифры)
Четыре герой-карточки: точность на holdout 97.2% (69/71), MAE 4.30, стабильность 99%, $0.021 за диалог. Карточки въезжают по одной на шаг, число одометром. Под каждым числом мини-график из данных (полоска 69 из 71, шкала стабильности). Добавь **октагон**: 8 сегментов собираются из центра, каждый заполняется до своего значения для ru-020. Сегмент N/A становится серым и «отдаёт» вес соседям: они чуть растут, а итог пересчитывается одометром 60 → 92.31. Это наш главный аргумент про N/A, сделай его самым красивым движением в деке.

### 4.11 ours (что наше)
Список «наше» из `facts.json` как сетка плиток. На каждом шаге плитка переворачивается (rotateY 180°, перспектива 1200 px): спереди короткое название, сзади одна строка «почему это важно». Иконки из `icons.ts` прорисовываются штрихом.

### 4.12 next
Строки плана проявляются маской. QR-код в конце собирается из модулей с диагональным stagger за 600 мс. На PNG он должен быть цельным и сканироваться.

### 4.13 Бегущая строка (общая, по желанию)
Внизу титула и финала тонкая лента: `c1 contact · c2 discovery · c3 identification · …` JetBrains Mono 18 px, `--text-3`, скорость 40 px/с, бесшовная. На остальных слайдах ленты нет.

## 5. Микродетали, которые делают «дорого»

- Номер слайда `03 / 11` в углу, JetBrains Mono. При смене цифры прокручиваются как у одометра.
- Курсор в режиме ведущего скрыт. Он появляется при движении мыши и прячется через 2 с.
- Тени только из `--shadow`. При въезде карточка «опускается» на стол: тень от 0 до полной за `--t-2`.
- Шумовая текстура фона (SVG feTurbulence, прозрачность 3%) убирает «пластик» на проекторе. Пусть её можно выключить одной переменной.
- Все подписи на графиках выровнены по базовой линии сетки 8 px.

## 6. Производительность и проверка

1. Цель 60 fps на ноутбуке с RTX 5070 Ti и на проекторе 1920×1080. В DevTools Performance на слайде архитектуры не должно быть long tasks больше 50 мс.
2. Сборка: `npm run all` (build, export, check). Размер `dist/index.html` после сборки не должен вырасти больше чем на 30% от текущего. Если вырос, подключи шрифты сабсетами (latin и cyrillic).
3. Проверь глазами каждый PNG в `dist/png/`: финальный кадр полный, текст не обрезан, кириллица в цитатах в Source Serif.
4. Включи `prefers-reduced-motion: reduce` в DevTools и пройди деку: всё читается, ничего не дёргается.
5. Пройди деку пробелом от начала до конца два раза подряд. Повторный заход на слайд снова проигрывает анимацию с шага 1. Возврат назад (стрелка влево) показывает предыдущий шаг сразу, без проигрывания.
6. Закоммить отдельным коммитом `pitch: motion v2 (typography, odometer, octagon, view transitions)`. В `pitch/slides/README.md` допиши раздел «Движение»: токены, `motion.ts`, как отключить.
