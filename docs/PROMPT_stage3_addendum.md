## 1. Обязательная выгрузка результатов (главное, влияет на оценку)

В корне репозитория должны лежать:
```
results/dev/results.json    # 65 записей: 60 чатов + 5 звонков DEV
results/prod/results.json   # ровно 10 записей контрольного набора
```
Формат (schema_version 1.0, менять названия полей, коды критериев и типы нельзя):
```json
{
  "schema_version": "1.0",
  "team_name": "<из .env TEAM_NAME>",
  "model": {"mode": "hybrid", "name": "google/gemini-3.8-flash, openai/gpt-6.1-sol, google/gemini-4-argon"},
  "results": [
    {
      "conversation_id": "p1-ru-009",
      "status": "ok",
      "criteria": [
        {"criterion_id": "contact", "value": true, "rationale": "...", "evidence_turns": [10]},
        {"criterion_id": "discovery", "value": true, "rationale": "...", "evidence_turns": [10]},
        {"criterion_id": "identification", "value": false, "rationale": "...", "evidence_turns": [12, 13, 14]},
        {"criterion_id": "consultation", "value": 5, "rationale": "...", "evidence_turns": [12, 14, 16]},
        {"criterion_id": "empathy", "value": false, "rationale": "...", "evidence_turns": [11, 15]},
        {"criterion_id": "dialogue", "value": 4, "rationale": "...", "evidence_turns": [12, 14]},
        {"criterion_id": "closure", "value": true, "rationale": "...", "evidence_turns": [16]},
        {"criterion_id": "critical", "value": true, "rationale": "...", "evidence_turns": [12]}
      ],
      "score": {"final_score": 41.0, "critical_flag": true}
    }
  ]
}
```
Правила:
- Коды: c1 `contact`, c2 `discovery`, c3 `identification`, c4 `consultation`, c5 `empathy`, c6 `dialogue`, c7 `closure`, c8 `critical`. Добавь в модель критерия поле `export_code`; у стандартного чек-листа оно равно этим кодам, у новых критериев задаётся в редакторе.
- `value`: true = Да, false = Нет, null = N/A, число = ступень шкалы до учёта веса (`consultation` 0, 5, 10, 15, 20 или null; `dialogue` 0, 4, 7, 10). `contact`, `empathy`, `critical` только true или false.
- **`evidence_turns` нумеруются с 1** по исходному массиву transcript, включая client, bot и system. Внутри системы мы храним idx с 0, значит при экспорте `+1`. Добавь тест на это. Это легко потерять, проверь отдельно.
- `final_score` от 0 до 100, два знака, округление половина вверх (организаторы подтвердили: 50,625 → 50,63). N/A исключается, вес перераспределяется. Если применимых нет, `final_score: null`.
- `critical_flag` равен value критерия `critical` и не обнуляет итог.
- `model.mode`: `external_api`, `local` или `hybrid`. В `name` фактически использованные модели через запятую.
- Ошибка оценки диалога: `{"conversation_id": "...", "status": "error", "criteria": [], "score": null, "error": "причина"}`. Не пропускать диалог и не подменять нулём.
- Для `status: "ok"` все 8 критериев ровно по одному разу. Одна запись на диалог, без повторов ID, ID точь-в-точь как в API. UTF-8, валидный JSON.

Сделай:
1. `GET /api/export/results?set=dev|prod&checklist_id=&version=` и CLI `python -m app.cli export --set dev|prod --group <group_id>`: импорт → оценка всех диалогов набора (с кешем) → запись `results/<set>/results.json`.
2. CLI `python -m app.cli validate-results results/prod/results.json --expect 10`: проверяет схему, типы значений по каждому коду, нумерацию evidence с 1 и границы по длине транскрипта, отсутствие дублей, пересчитывает `final_score` нашим `scoring.py` и сверяет.
3. Скрипт `scripts/control_run.sh <group_id>`: export prod → validate → `git add results && git commit -m "prod results" && git push`. На контроль будет **1 час** до стоп-кода 12:00, включая получение данных, оценку, проверку и push. Прогон должен укладываться в 10 минут; проверь время на 10 диалогах DEV.
4. Сразу сгенерируй и закоммить `results/dev/results.json` по всем 65 DEV-диалогам, когда движок готов.

## 2. Уточнения трактовок от Freedom (в `guidance` критериев, не в код)
- c7 Завершение: только прощание («Пожалуйста. Хорошего вечера!», «Bye.») без итога и без предложения помощи = **Нет**. N/A только если чат оборвался до возможности завершить.
- c2 Выявление потребности: клиент сразу дал все детали (в том числе боту), оператор ответил без уточнений = **N/A**. Переспросил уже известное = Нет.
- c3 + c8: оператор сообщил данные счёта (например, ограничение на вывод) до идентификации = c3 **Нет** и c8 **Да** (раскрытие конфиденциальной информации). Страховка ансамбля из основного промпта (c3=N → c8 к арбитру) остаётся.
- Идентификация: клиент не считается верифицированным только потому, что пишет из приложения. Рассматривать омниканальную систему.
- Порог первой реакции 3 минуты это SLA. Отдай сигнал «первая реакция оператора после эскалации > 180 с» в контекст c6 (скорость, предупреждение об ожидании). Теги и вложения в оценку не входят.
- Норматива длительности удержания в звонках нет.
- c4: база знаний у Freedom есть, но участникам не выдана. Система не должна придумывать факты: если утверждение оператора нельзя проверить по диалогу, оценивай логику и полноту ответа, а в reasoning пиши, что факт не проверялся.
- Звонки: в контроле **только 10 чатов**. Звонки нужны для интерфейса (плеер, переход к фрагменту) и DEV-выгрузки; идеального распознавания организаторы не ждут. `contact` в выгрузке всегда true или false: если приветствие не попало в запись, оценивай по первой реплике оператора в записи.
- Сравнение с эталоном идёт **по ответу на каждый критерий**. Организаторы не ждут совпадения до балла и смотрят на адекватность и обоснованность.
- После замены критерия обработанные диалоги нужно переоценить по новому чек-листу. Сделай «переоценить только изменённые критерии» (дёшево), а полную переоценку оставь опцией.
