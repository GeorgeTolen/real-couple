# Этап 2а — выбор модели (бенчмарк на DEV, 2026-11-07)

## Метод
- 12 DEV-чатов (6 RU, 3 KZ, 3 EN), ручная эталонная разметка по 8 критериям (bench/gt_manual.json); спорные пункты помечены «?» и исключены из точности.
- Один промпт для всех: полный чек-лист, строгий JSON (evidence_ids → reasoning → answer), temperature 0, reasoning effort medium, OpenRouter.
- Метрики: точность по критериям (уверенная разметка), MAE итогового балла (0–100, перераспределение весов при N/A), стоимость и время на диалог, стабильность при повторном прогоне.
- Ограничение: 12 диалогов и один разметчик; разница в 1–2 п.п. = шум.

## Наблюдения
- Сложнее всего (все модели вместе): c4 «Консультация» — 77%, c6 «Ведение диалога» — 84%. c3 «Идентификация» — 100%, c8 — 98%, c7 — 97% (на уверенных пунктах).
- Итоговая ошибка в баллах почти целиком из c4 и c5 (самые тяжёлые веса). Terra мягче всех ставит c4 (например, p1-ru-009: 20 при раскрытии данных без ответа) → большой MAE.
- Gemini 3.8 Flash дважды пропустил грубую ошибку в p1-ru-009 (раскрытие данных счёта без идентификации) → страховка: c3=N → c8 уходит арбитру.
- Спорные пункты (ждать ответов Фридома): c7 для «Пожалуйста. Хорошего дня!» (большинство моделей: НЕТ); c2 NA vs N; ступени c4.
- Claude Sonnet/Haiku 5.5 на этой задаче заметно слабее, Opus сильный, но в 4 раза дороже лидеров.

## Решение
- Ансамбль: A = google/gemini-3.8-flash, B = openai/gpt-6.1-sol, арбитр по спорным критериям = google/gemini-4-argon (~$0.017–0.02/диалог).
- Локальный режим: Gemma 4 26B-A4B через Ollama/llama.cpp.
