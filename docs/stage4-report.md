## 2. Как проверить

Нужны готовая база `data/cqa.sqlite` и ключ OpenRouter. Сервер для тестов поднимается сам на копии базы, рабочие данные не меняются.

```bash
cd backend && ../.venv/Scripts/python -m pytest -q      # 96 passed
cd frontend && npm run build                            # один HTML, 1,31 МБ
cd frontend && npm run e2e                              # 16 passed, несколько центов на один вызов модели
```

Скриншоты экранов лежат в `docs/screens`.

## 3. Что нашла проверка

Эти ошибки найдены проверками и исправлены:

- Поиск без результатов говорил «Диалогов пока нет, импортируйте набор», хотя диалоги были.
- Число в центре октагона перекрывало вершины с нулевым баллом и мешало наведению.
- Выноски на дорожках перекрывали метки соседней дорожки.
- Белый текст на кнопках цвета `#138a4e` давал контраст ниже 4,5:1. Фон кнопок теперь `#0e6b3c`, токен акцента не менялся.
- Транскрипт нельзя было прокрутить с клавиатуры.
- Блок «Почему снижена оценка» показывал длинный текст. Теперь это предложение со сбоем в две строки, полный текст есть в паспорте.
- Аналитика после правки чек-листа показывала только версию с единицами оценок. Теперь по умолчанию берётся самая полная версия.

Отдельно: в PNG из `docs/design` была метка происхождения в блоке `caBX`. Перед коммитом она удалена, данные изображения не менялись, это проверено сравнением хеша блоков `IDAT`.

## 4. Что не сделано или сделано иначе

1. **Скиллы `frontend-design` и `webapp-testing` в сессии отсутствуют.** Playwright поставлен в devDependencies, как предусмотрено заданием.
2. **Время кадра меньше 2 мс не подтверждено.** Измерено только время JavaScript на кадр: 0,5 до 0,7 мс при программной отрисовке в тесте. Время видеокарты не измерялось.
3. **three.js не вынесен в отдельный файл.** `vite-plugin-singlefile` собирает всё в один HTML, поэтому код сцены входит в него: 1,31 МБ при лимите 2,5 МБ. Импорт динамический, сцена создаётся только там, где нужна, но файл загружается целиком.
4. **«Как улучшить» не генерируется моделью.** Это следующая ступень шкалы или описание критерия из чек-листа. Новое поле ответа модели потребовало бы платной переоценки всего DEV.
5. **Пустого состояния «Выберите диалог» нет.** В продукте список и карточка это разные страницы. Монеты стоят в пустом списке, в неоценённом диалоге, при пакетной оценке и на странице 404.
6. **Ось карты по умолчанию задана кодом критерия, а не полем в файле чек-листа.** Правка файла создала бы новую версию, и экспорт DEV начал бы отказывать до платной переоценки. В редакторе ось можно задать явно. Критерий без кода организаторов на карту не попадает, пока ось не указана.
7. **Типографика.** Подписи полосы метрик 11 px заданы заданием, это четвёртый размер. Текст внутри SVG масштабируется вместе с графиком, поэтому к правилу трёх размеров он не приводится.
8. **Отступы проверяются только в `app.css` и частично вручную в разметке.** Радиусы вложенных элементов проверяются для таблиц и предупреждений внутри карточек, а не для всех сочетаний.
9. **Доступность.** Служебные элементы фокуса Fluent UI (`data-tabster-dummy`) и `canvas` исключены из проверки axe. Автоматическая проверка не заменяет ручную с экранным диктором, её не было.
10. **Волны звука нет.** Запись одноканальная, дорожки построены по транскрипту. Выноски показывают до двух моментов выбранного критерия.
11. **Режим «Центры операторов» малоинформативен на DEV.** Почти у каждого оператора по одному диалогу, поэтому разброс виден слабо.
12. **Покрытие браузерных тестов.** Кнопка «Пересчитать заново» не нажималась, потому что это платно. Запасной режим при отсутствии WebGL проверен только через уменьшенное движение, а не при реально отключённом WebGL.
13. **Запуск на другом браузере и на Linux не проверялся.** Тесты шли в Microsoft Edge на Windows с программной отрисовкой.

## 5. Что не менялось

`results/dev/results.json` и файл чек-листа не изменены, новая версия чек-листа не появилась, переоценка не требуется. Правки не влияют на промпты и ответы моделей.
