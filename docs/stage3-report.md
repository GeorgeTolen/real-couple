## 2. Как проверять

Команды для PowerShell, из корня клона. Для чистого клона сначала `make install` и файл `.env` по `.env.example`. Сначала выполните:

```powershell
cd backend
$env:PYTHONUTF8=1
```

### Бесплатно и без изменения данных

| Что проверить | Команда | Ожидаемый результат |
|---|---|---|
| Тесты, сеть не нужна | `..\.venv\Scripts\python -m pytest -q` | `89 passed` |
| Эталон зафиксирован до прогона | `git log --format="%cI %s" -- bench/holdout/gt_holdout.json bench/holdout/holdout_report.json` | Эталон в коммите от 00:57, отчёт о прогоне в более позднем коммите. Хеши изменились при очистке истории, даты сохранены |
| Ключ в истории | `git log --all -p -G "sk-or-v1-[0-9a-f]{8}" --format=%h` | Пусто |
| Лишние файлы в истории `main` | `git log main --name-only --format= \| Select-String "sqlite\|data/audio\|data/whisper\|data/dev.json\|Student_Guide_v3"` | Пусто |
| Подписанные ссылки в истории `main` | `git log main -p -G "powerplatform\.com\|crm11\.dynamics" --format=%h` | Пусто |

В базе чистого клона данных нет. Проверки `validate` и интерфейса требуют `make import` и оценки, то есть ключа и денег. Сам файл результатов можно прочитать сразу, а его формат и пересчёт проверяет тест и команда `validate` при наличии импорта.

### Платно или с изменением данных

| Команда | Что сделает |
|---|---|
| `make evaluate-all` | Около $1,6 и 10 минут на чистой базе |
| `make holdout` | Около $0,23, отдельная база `data/holdout.sqlite`, при готовой базе берёт сохранённые оценки |
| `python -m app.cli bench --mode ensemble --repeat 2` | Около $0,55, новые записи, перезапись `bench/results_ensemble.json` |
| `python -m app.cli prod --group <id>` | Настоящий коммит и пуш в `main` |

Сквозной тест браузера не входит в репозиторий, он лежал во временной папке сессии.

## 5. Известные проблемы и решения

### Важно для сдачи

1. **Решения проверяющих больше не попадают в файл сдачи.** Это отступление от плана, где файл строился по финальному слою. Причина: пробная апелляция на `p1-en-014` сняла грубую ошибку, и это попало в результаты. Теперь в файле ответы модели, решения включаются флагом `--with-decisions`. Если организаторы ждут финальные оценки с решениями, поведение нужно вернуть.
2. **Персональные данные в Whisper.** Текст скрыт по умолчанию, на местах масок стоят маски, сырые слова не хранятся. Проверка пяти записей: проверенные имена и длинные числа не найдены. Это эвристика: имя строчными буквами вне маски может остаться, а обычные слова с большой буквы иногда скрываются лишними масками. Whisper по-прежнему работает с аудио, где эти данные звучат.
3. **Утечка ссылок на звонки.** Старая история с `data/dev.json` и гайдом была в открытом репозитории примерно с 01:08 до момента, когда владелец сделал его приватным. По данным GitHub на 01:20 просмотров, клонов и форков нет, но счётчики обновляются с задержкой. Старые коммиты могут оставаться доступны на GitHub по прямому хешу и после принудительного пуша. Полностью убрать их может только удаление репозитория или поддержка GitHub. Ключ OpenRouter в git не попадал, но был отправлен в чат, его стоит отозвать после хакатона.
4. **Пуш в час контроля проверен не на настоящем `origin`.** Проверка шла на отдельном клоне с локальным удалённым репозиторием. Импорт контрольного `group_id` не проверялся, потому что он ещё не выдан.

### Прочие ограничения

5. **На чистой установке нет данных.** База не входит в git, жюри нужен ключ и около $1,6 на оценку, либо показ на ноутбуке команды. README теперь описывает импорт и оценку.
6. **В базе смешаны версии после правок.** Список показывает последнюю оценку каждого диалога. После новой версии чек-листа счётчики в шапке считаются по смеси, пока диалоги не переоценены.
7. **Локальный режим не измерен.** На экране запуска для него написано «нет замера». Остальные цифры читаются из файлов бенчмарка с датой и числом диалогов.
8. **PDF с чек-листом организаторов среди файлов не было.** Тексты критериев взяты из `docs/PROMPT_stage3_backend.md`, сверки с оригиналом нет.
9. **Docker не собирался:** на машине его нет. Запуск на Linux не проверялся.
10. **Метрики речи приблизительны.** Темп и перебивания считаются по меткам времени транскрипта.
11. **Выравнивание Whisper ошибается на коротких искажённых репликах.** Пример: в `p4-ru-001` у #17 нет текста, а у #18 два раза «Мирас».
12. **Интерфейс без автотестов в репозитории.** Проверка типов идёт при сборке, сквозной тест лежит вне git.
13. **Правило флага «На проверку» изменено по просьбе владельца.** Флаг ставится, только если арбитр не согласился ни с одним судьёй, кто-то из моделей был недоступен или сбой не назван. Старые оценки пересчитаны без вызова моделей. Цена такого правила: случаи, где арбитр просто выбрал сторону, больше не попадают к человеку.
14. **Слабое место модели: c2 и ступени c4.** Это видно и на контрольном наборе, и на калибровочном.

## 6. Что особенно стоит проверить

1. Верно ли применены трактовки организаторов. Исходная переписка мне недоступна, я знаю её по пересказу в `docs/PROMPT_stage3_addendum.md`.
2. Совпадают ли тексты критериев с настоящим PDF чек-листа.
3. Нет ли в `checklists/freedom_default.json` подгонки под конкретные диалоги. Часть примеров в подсказках взята из разъяснений и файла калибровки.
4. Корректен ли `results/dev/results.json` на выборке: номера реплик считаются с 1 и должны указывать на реплику из объяснения.
5. Согласны ли вы с эталоном контрольного набора. Лучше всего разметить `bench/holdout/holdout_chats.json` заново, не глядя в `gt_holdout.json`.
6. Нужны ли организаторам в файле ответы модели или финальные оценки, см. проблему 1.
