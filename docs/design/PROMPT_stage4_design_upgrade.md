# Этап 4: доработка дизайна. Тенге в 3D, октагон, карта диалогов, разгрузка интерфейса

Отдай агенту целиком. Работать в `frontend/` и немного в `backend/` (только эндпоинты аналитики).

## 0. Скиллы и порядок
1. Если в сессии есть скилл **frontend-design**, загрузи его до первой строки кода и следуй ему в части типографики, композиции и состояний.
2. Для проверки в браузере используй скилл **webapp-testing** (Playwright), если он есть. Если нет, поставь `@playwright/test` в devDependencies и пиши тесты сам.
3. Перед кодом открой и изучи референсы в `docs/design/`:
   - `reference_dark_tenge.html` и `reference_dark_tenge_screenshot.png`: тёмно-зелёная тема и кольцо монет ₸ (классы `.coin-scene`, `.coin-ring`, `.coin`, анимация `coins-turn`). Монеты там плоские CSS-диски с градиентом, объёма нет;
   - `mockup_dialog_octagon_map.png`: октагон с выносками, паспорт критерия, плотность распределения из точек, карта «Решение вопроса × Сервис»;
   - `mockup_call_octagon.png`: звонок, две дорожки, октагон с карточками критериев вокруг;
   - `rule_nested_radius.png`: правило радиусов вложенных элементов.
4. Сначала план правок по экранам (короткий список), потом код. После каждого шага `npm run build` и скриншоты.

## 1. Что сохраняем (ядро дизайна, не ломать)
- Стек: React 19, Fluent UI v9, Vite, `vite-plugin-singlefile`. Один HTML-файл на выходе, совместимость с HTML web resource Dynamics 365.
- Токены из `src/app.css`: светлая основа `--bg #f6f5f1`, карточки `#fff`, линии `#e3e1da`, акцент `#138a4e`, тёмная навигация `#0e3b27`, цвета статусов `--yes/--no/--na/--mid`, моноширинный шрифт для чисел.
- Структура страниц и роутов, все текущие функции: список, карточка диалога, звонок, грубые нарушения, пакетная оценка, чек-листы, апелляции, аналитика.
- Контент остаётся светлым. Тёмно-зелёный используется только для «хрома»: навигация, верхняя полоса метрик, пустые состояния и экран ожидания пакетной оценки.

## 2. Дизайн-правила (внести в `app.css` токенами и соблюдать везде)
1. **Радиусы вложенных элементов:** внешний радиус = внутренний радиус + отступ. Токены: `--r-outer: 12px`, `--pad-card: 8px` → `--r-inner: 4px`; карточка 8px с отступом 4px → вложенный 4px. Чипы и бейджи 4px. Никогда одинаковый радиус у карточки и элемента внутри.
2. Сетка 8px: отступы 4, 8, 12, 16, 24, 32. Других значений нет.
3. Типографика: на экране максимум 3 размера текста (12, 14, 20) плюс крупное число итога. Все числа, ID, время и баллы моноширинные с табличными цифрами.
4. Цвет только со смыслом: зелёный норма, красный нарушение, янтарный на проверку, серый N/A. Декоративного цвета нет.
5. Одно главное действие на экран (акцентная кнопка), остальные вторичные.
6. Постепенное раскрытие: на экране ответ на главный вопрос, детали по наведению, раскрытию строки или во вкладке «Детали». Модели, стоимость, версии промпта уходят во вкладку «Детали», не в шапку.
7. Предсказуемое место: заголовок и статус слева сверху, главное действие справа сверху, фильтры одной строкой под заголовком.
8. У каждого пустого состояния есть подсказка, что делать дальше, и кнопка этого действия.
9. Доступность: контраст AA, видимый фокус, всё работает с клавиатуры, `aria-label` у иконок и SVG-графиков, `prefers-reduced-motion` отключает анимации.
10. Никаких длинных тире в интерфейсных текстах, коротко и по делу.

## 3. Разгрузка интерфейса (аудит и правки)
Пройди каждый экран и ответь в плане: «на какой один вопрос отвечает экран». Убери то, что не помогает этому ответу.
- Шапка карточки диалога: ID, статус, оператор, канал, язык, итог. Модели, цена, время оценки во вкладку «Детали».
- Список диалогов: колонки ID, оператор, канал и язык одной ячейкой, итог с полоской, 8 квадратиков критериев, флаги. Дата и длительность мельче. Счётчики сверху одной строкой.
- Повторяющиеся легенды и подписи объедини; одна легенда на экран.
- Блок «Почему снижена оценка» максимум 3 строки, каждая со ссылкой «Перейти к фрагменту».
- Бейдж «На проверку» показывай только если `needs_review` и это реально требует человека (см. бэкенд); иначе тихая точка расхождения моделей.

## 4. Новые компоненты

### 4.1 Монеты ₸ в объёме (`components/TengeCoins.tsx`)
Заменить плоские диски на настоящие 3D-монеты.
- Технология: **three.js**, загружать динамическим `import()` только на экранах, где сцена видна; при отсутствии WebGL или при `prefers-reduced-motion` показывать статичную SVG/CSS-версию.
- Геометрия монеты: диск с толщиной и фаской (`ExtrudeGeometry` по кругу с `bevelEnabled`), рифлёный гурт (мелкие насечки по ребру через normal map или повтор геометрии), на обеих сторонах выпуклый знак ₸ (собрать как `Shape`: две горизонтальные планки и вертикальная ножка от второй планки вниз, `ExtrudeGeometry` с небольшой фаской), тонкий внутренний ободок.
- Материал: металл в цвете ядра бренда. `MeshPhysicalMaterial` или `MeshStandardMaterial`, metalness 0.85 до 0.95, roughness 0.28 до 0.4, базовый цвет от `#0e3b27` до `#138a4e`, блики светло-зелёные `#a5c9ad`. Знак ₸ чуть светлее поля (как чеканка). Освещение: `RoomEnvironment` через `PMREMGenerator` плюс один направленный свет; мягкая тень под кольцом.
- Композиция: кольцо из 10 до 12 монет в наклонной перспективе, как в референсе, медленное вращение (период около 20 с), лёгкое покачивание монет; при наведении мыши кольцо чуть поворачивается за курсором (параллакс до 6 градусов).
- Производительность: `devicePixelRatio` не выше 2, рендер останавливается, когда компонент не виден (IntersectionObserver) и когда вкладка скрыта; меньше 2 мс на кадр на ноутбуке.
- Где использовать: пустое состояние списка и карточки («Выберите диалог»), экран ожидания пакетной оценки (скорость вращения растёт с прогрессом, по завершении монеты останавливаются лицевой стороной), страница 404. Не использовать фоном за таблицами и графиками.
- Фон сцены тёмно-зелёный из референса (`#071b16` до `#0c261f`) в карточке с радиусом по правилу 2.1.

### 4.2 Октагон качества (`components/QualityOctagon.tsx`, SVG, без библиотек графиков)
- N-угольник по числу критериев с весом из текущей версии чек-листа (8 → восьмиугольник, 9 → девятиугольник). Флаговые критерии (грубые) отдельной вершиной.
- Уровни 25, 50, 75, 100; профиль диалога заливкой акцента 12%; вершины: выполнено зелёная точка, частично янтарная, не выполнено красная, N/A полый пунктирный кружок на внешнем контуре (не ноль). В центре итог моноширинным шрифтом «из 100».
- Выноски от вершин к компактным карточкам критериев (название, ответ, баллы после веса «10,5 / 15», ступень мелко «7 из 10»). На узких экранах выноски скрываются, остаётся список.
- Наведение или фокус на вершине открывает **паспорт критерия**: код и вес, шкала со ступенями и ромбиком ответа модели, «Почему» с чипами реплик, «Как улучшить» (только если баллы потеряны), согласие моделей. Клик по чипу прокручивает транскрипт к реплике.
- В карточке диалога: переключатель вида «Схема / Список», по умолчанию «Схема». Текущий список критериев остаётся вторым видом.
- В редакторе чек-листа: живой предпросмотр октагона, перестраивается при добавлении критерия и смене веса.

### 4.3 Плотность распределения (`components/ScoreDensity.tsx`)
Распределение итоговых баллов как рельеф из точек (как на макете): ось 0..100, медиана пунктиром с подписью, порог 70. Каждый диалог даёт облако точек по ядерной оценке плотности (детерминированный псевдослучайный разброс с фиксированным seed, чтобы картинка не прыгала). Наведение на столбец точек: «баллы 80..85: 14 диалогов», клик фильтрует список.

### 4.4 Карта диалогов (`components/DialogMap.tsx`)
- Ось X «Решение вопроса», ось Y «Сервис», 0..100. Эталон чек-листа ромбом в (100, 100), зона нормы от 85 по обеим осям.
- Точка на диалог: цвет по итогу, красное кольцо при грубом нарушении, янтарный при `needs_review`. Совпадающие точки раздвигаются, у группы счётчик.
- Пунктир к эталону у проблемных точек (итог ниже 70). Подписи только у выбранной и трёх худших.
- Режим «центры операторов»: крестик и облако разброса на оператора.
- Режим «сдвиг при смене чек-листа»: выбор двух версий, точки парами с тонкими стрелками.
- Клик по точке открывает карточку диалога.

### 4.5 Полоса метрик в тёмно-зелёном (`components/KpiStrip.tsx`)
По макету: тёмно-зелёная полоса под верхней панелью на экранах «Диалоги» и «Аналитика»: всего диалогов, чаты / звонки, языки RU / KZ / EN, средний балл, на проверку, грубые нарушения, точность на тестовом наборе, цена оценки. Значения моноширинные, подписи заглавными 11px. Точность и цена берутся из файла бенчмарка через API, с подписью «замер N диалогов, дата», не из кода.

## 6. Бэкенд (минимум)
- Поле критерия `map_axis`: `resolution` или `service` (по умолчанию c2, c3, c4 → resolution; c1, c5, c6, c7 → service; флаги без оси). Редактируется в чек-листе.
- `GET /api/analytics/map?checklist_id=&version=`: на диалог `id, operator, channel, language, total, x, y, gross, needs_review`. x и y считаются тем же кодом, что итог (взвешенная доля по критериям оси, N/A исключается).
- `GET /api/analytics/distribution?...`: список итоговых баллов и медиана.
- `GET /api/analytics/benchmark`: точность, MAE, стабильность, размер выборки, дата из `bench/results_*.json`.
- Тесты на расчёт осей, включая N/A и пустую ось.

1. `npm run build` без ошибок; итоговый HTML не больше 2,5 МБ (three.js в отдельном динамическом чанке, если singlefile это позволяет; иначе указать размер в отчёте).
2. Playwright: скриншоты 1440×900 всех экранов в `docs/screens/` (для README и питча); сценарии: наведение на вершину октагона открывает паспорт; клик по чипу реплики прокручивает транскрипт; клик по точке карты открывает диалог; добавление критерия в редакторе перестраивает октагон в девятиугольник; при `prefers-reduced-motion` монеты статичны.
3. Проверка правил: нет одинаковых радиусов у вложенных элементов, отступы только из сетки, один акцент на экран.

Не тратить время на: тёмную тему для всех экранов целиком, мобильную вёрстку глубже «не ломается на 1280px», новые библиотеки графиков.
